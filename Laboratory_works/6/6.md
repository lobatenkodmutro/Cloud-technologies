**2.1. Що таке віртуальна машина та які особливості їх реалізації у Azure Virtual Machine?** <br>
**Віртуальна машина (Virtual Machine, VM)** являє собою повністю ізольоване програмне середовище, яке імітує функціонал фізичного сервера і виконується під контролем гіпервізора в хмарній інфраструктурі. Вона володіє власною конфігурацією обчислювальних ресурсів (vCPU, RAM, дискові накопичувачі, мережеві адаптери) і відповідає концепції **IaaS (Infrastructure as a Service)**, надаючи користувачеві абсолютні адміністративні права для встановлення й налаштування операційної системи (Linux або Windows) та довільного ПЗ.

**Ключові архітектурні особливості реалізації Azure Virtual Machine (Azure VM):**
1. **Апаратна платформа та гіпервізор:** Хмара Azure спирається на кастомізовану версію гіпервізора Microsoft Hyper-V і технологію апаратного розвантаження **Azure Boost** (яка делегує дискові й мережеві операції введення-виведення спеціалізованим мікроконтролерам SoC, вивільняючи CPU для завдань користувача).
2. **Градація серій та розмірів (VM Sizes):**
   * *General Purpose (серії B, D):* оптимальний баланс ядер та оперативної пам'яті (серія B підтримує динамічне накопичення кредитів продуктивності Burstable для нерівномірних навантажень);
   * *Compute Optimized (серія F):* висока тактова частота процесорів для математичних обчислень, кодування відео та ігрових серверів;
   * *Memory Optimized (серії E, M):* значний обсяг RAM для кешуючих систем і реляційних СУБД (SAP HANA, SQL Server);
   * *GPU Accelerated (серії NC, ND, NV):* графічні прискорювачі NVIDIA для завдань штучного інтелекту, рендерингу та 3D-візуалізації.

**2.2. Які можливості надає Azure App Service?** <br>
**Azure App Service** являє собою повністю керовану PaaS-платформу (Platform as a Service), призначену для розгортання та автоматичного хостингу веб-додатків, REST API й мобільних бекендів без потреби налаштовувати операційні системи чи сервери.

**Основні функціональні можливості Azure App Service:**
1. **Мультимовна підтримка стеків:** Нативна сумісність із Node.js, Python, .NET Core, Java, PHP, Ruby, а також запуск довільних кастомних Docker-контейнерів (Linux/Windows).
2. **Автоматичне масштабування (Autoscaling):** Гнучке керування ресурсами — горизонтальне (Scaling Out — додавання нових інстансів) або вертикальне (Scaling Up — зміна тарифного плану) за розкладом чи показниками завантаження.
3. **Інтеграція CI/CD:** Автоматизація розгортання завдяки вбудованому підключенню до GitHub, Azure DevOps, Bitbucket та Docker Hub.
4. **Вбудовані засоби безпеки:** Безкоштовна активація SSL/HTTPS-сертифікатів, підтримка автентифікації через Microsoft Entra ID (Azure AD), Google, Facebook, збереження секретів у Azure Key Vault та ізоляція через закриті віртуальні мережі (VNet Integration).

**2.3. Які основні кроки створення App Service через портал Azure?** <br>
Покроковий алгоритм розгортання веб-сервісу через графічний інтерфейс Azure Portal включає такі етапи:
1. **Ініціалізація створення:** У головному пошуковому рядку Azure Portal ввести `App Services`, відкрити сервіс та натиснути **+ Create -> Web App**.
2. **Налаштування параметрів (вкладка Basics):**
   * **Subscription:** обрання активної підписки (наприклад, Azure Free Subscription);
   * **Resource Group:** вибір наявної групи ресурсів або створення нової;
   * **Name:** визначення унікальної веб-адреси (наприклад, `mywebapp.azurewebsites.net`);
   * **Publish:** вибір способу публікації — *Code* (вихідний код) або *Docker Container*;
   * **Runtime stack:** вибір програмного середовища (наприклад, .NET 8, Node.js 20, Python 3.11);
   * **Operating System:** вибір платформи Linux або Windows;
   * **Region:** вибір найближчого регіону дата-центру (наприклад, *West Europe*).
3. **Вибір тарифного плану (App Service Plan):** Визначення конфігурації обчислювальних ресурсів, обсягу RAM та функціональних можливостей (наприклад, безкоштовний тариф Free F1 чи продуктивний Basic/Standard).
4. **Налаштування CI/CD (за потреби):** Підключення репозиторію GitHub або Azure Repos для автоматичного розгортання при push-подіях.
5. **Фінальна перевірка та деплой:** Перевірка введених даних у меню **Review + create** та натискання кнопки **Create** для запуску процедури створення.

**2.4. Які особливості реалізації "Access control (IAM)" в Azure?** <br>
Контроль доступу та розмежування прав у середовищі Azure реалізовано за допомогою модельної системи **Azure RBAC (Role-Based Access Control)**, яка гарантує надання гранульованих привілеїв користувачам, групам та сервісам.

**Ключові аспекти функціонування Azure RBAC:**
1. **Три складові елементи призначення прав (Role Assignment):**
   * *Security Principal (Суб'єкт):* Об'єкт, якому надаються права (користувач, група, Managed Identity чи Service Principal).
   * *Role Definition (Роль):* Перелік дозволених або заборонених дій (Actions / NotActions).
   * *Scope (Область дії):* Рівень ієрархії інфраструктури, на який поширюються права (Management Group -> Subscription -> Resource Group -> Resource).
2. **Категорії базових ролей (Built-in Roles):**
   * *Owner (Власник):* Повний контроль над ресурсами, у тому числі управління правами доступу інших суб'єктів.
   * *Contributor (Учасник):* Повні права на створення, редагування та видалення ресурсів без можливості змінювати дозволи.
   * *Reader (Читач):* Перегляд конфігурацій та параметрів об'єктів без права правки чи видалення.
3. **Принцип ієрархічного успадкування:** Права, призначені на верхньому рівні (наприклад, на рівні підписки чи групи ресурсів), автоматично поширюються на всі вкладені елементи.

**2.5. Розкрийте використання Deployment slots для управління версіями.** <br>
**Deployment Slots (Слоти розгортання)** — це окремі паралельні екземпляри веб-додатка всередині одного App Service Plan, кожен з яких володіє власною унікальною URL-адресою (наприклад, `myapp-staging.azurewebsites.net`).

**Особливості та переваги використання:**
1. **Безшовне оновлення (Zero-Downtime Deployment):** Нова версія коду завантажується в ізольований слот `staging`. Після перевірки працездатності здійснюється операція **Swap (Заміна)**, яка миттєво перенаправляє реальний трафік на оновлений слот без простою сервісу.
2. **Безпечне тестування на реальних конфігураціях:** Слот `staging` дозволяє перевірити роботу системи перед виходом у продакшн.
3. **Швидкий відкат (Instant Rollback):** У разі виявлення критичних помилок після релізу повторний Swap миттєво відновлює попередній працездатний стан додатка.

**2.6. Здійсніть огляд Storage Account та його ключових функцій.** <br>
**Azure Storage Account** є уніфікованою хмарною службою для централізованого збереження неструктурованих, напівструктурованих та файлових даних із високими показниками надійності, доступності та масштабованості.

**Ключові характеристики та можливості Storage Account:**
1. **Механізми відмовостійкості та резервування:**
   * *LRS (Locally-Redundant Storage):* створення 3 копій даних у межах одного дата-центру;
   * *ZRS (Zone-Redundant Storage):* реплікація даних у 3 зонах доступності в межах одного регіону;
   * *GRS (Geo-Redundant Storage):* дублювання даних у віддалений вторинний регіон.
2. **Рівні зберігання даних (Access Tiers):**
   * *Hot:* для часто запитуваної інформації;
   * *Cool:* для даних із рідким доступом (збереження від 30 днів);
   * *Cold:* для даних із дуже рідким доступом (збереження від 90 днів із низькою ціною за гігабайт);
   * *Archive:* найдешевше архівне сховище (збереження від 180 днів, вимагає розконсервації).
3. **Безпека даних:** Автоматичне шифрування за замовчуванням (Storage Service Encryption — SSE) алгоритмом AES-256 та підтримка прив'язки до Private Endpoints.

**2.8. Опишіть як працювати з Azure Storage на прикладі використання мови C#.** <br>
Програмна взаємодія з об'єктним сховищем Azure у середовищі .NET здійснюється через офіційний пакет **Azure.Storage.Blobs**.

**Послідовність дій у коді C#:**
1. Підключення за допомогою рядка з'єднання (Connection String) або автентифікації `DefaultAzureCredential`.
2. Створення екземпляра `BlobServiceClient` для роботи зі службою.
3. Отримання об'єкта `BlobContainerClient` та його ініціалізація за відсутності.
4. Вивантаження або зчитування файлів через об'єкт `BlobClient`.

```csharp
using Azure.Storage.Blobs;
using System;
using System.IO;
using System.Threading.Tasks;

class Program
{
    static async Task Main(string[] args)
    {
        string connectionString = "DefaultEndpointsProtocol=https;AccountName=mystorageaccount;AccountKey=...;";
        string containerName = "lab-documents";
        string filePath = "report.txt";

        BlobServiceClient blobServiceClient = new BlobServiceClient(connectionString);
        BlobContainerClient containerClient = blobServiceClient.GetBlobContainerClient(containerName);
        await containerClient.CreateIfNotExistsAsync();

        BlobClient blobClient = containerClient.GetBlobClient("report.txt");
        await blobClient.UploadAsync(filePath, overwrite: true);
        Console.WriteLine("Файл успішно завантажено в Azure Blob Storage.");
    }
}
```

**2.9. Що таке Serverless та особливості їх реалізації у Azure Functions?** <br>
**Serverless (Безсерверні обчислення)** — це архітектурна модель, яка вивільняє розробника від адміністрування та масштабування серверної інфраструктури, виставляючи рахунок виключно за час виконання конкретної функції.

**Особливості реалізації в Azure Functions (FaaS):**
1. **Подієва модель (Event-Driven):** Виконання коду ініціюється тригерами: HTTP-запитами, таймерами (CRON), подіями в Blob Storage або повідомленнями з Queue/Service Bus.
2. **Концепція Triggers & Bindings:** Тригери запускають виконання, а вхідні й вихідні зв'язки (Bindings) дозволяють без написання шаблонного коду зчитувати чи записувати дані в хмарні сховища.
3. **Тарифікація Consumption Plan:** Оплата розраховується за кількість викликів та спожиту оперативну пам'ять (ГБ-секунди). При відсутності навантаження витрати дорівнюють нулю.

**2.10. Поясніть різницю між автентифікацією та авторизацією. Як пов'язані Azure RBAC та Entra ID (Azure AD) з цими поняттями?** <br>
* **Автентифікація (Authentication / AuthN):** Процес підтвердження особистості (хто намагається увійти у систему?). Вона перевіряє користувача через пароль, SMS-код чи біометрію.
* **Авторизація (Authorization / AuthZ):** Процес перевірки прав доступу (що підтвердженій особі дозволено робити?).

**Взаємозв'язок Entra ID та Azure RBAC:**
* **Microsoft Entra ID (Azure AD)** відповідає за **автентифікацію (AuthN)**. Сервіс перевіряє облікові дані, обробляє MFA та видає безпекові токени.
* **Azure RBAC** відповідає за **авторизацію (AuthZ)**. Він отримує токен від Entra ID та на основі призначених ролей вирішує, чи має користувач право виконувати дію над ресурсом.

##### Відповіді на контрольні питання

**<span>1. В чому суть TOTP аутентифікації? Наведіть приклади в контексті Microsoft Authenticator та Azure MFA (Multi-Factor Authentication).</span>** <br>
**TOTP (Time-based One-Time Password / Тимчасовий одноразовий пароль)** — це стандартизований алгоритм розрахунку одноразових динамічних паролів (специфікація RFC 6238), який базується на комбінації симетричного секретного ключа (Shared Secret) та поточного часового штампу (Unix Time). Код зазвичай складається з 6 цифр і є дійсним протягом 30 секунд, після чого автоматично змінюється.

**Застосування в Microsoft Authenticator та Azure MFA:**
* **Офлайн-генерація (OATH TOTP):** Додаток Microsoft Authenticator генерує коди без необхідності постійного підключення смартфону до мережі Інтернет у момент входу.
* **Захист від атак втоми (Number Matching):** Для відвернення атак типу MFA Fatigue (масове надсилання сповіщень) в Azure MFA реалізовано технологію **Number Matching (Зіставлення чисел)**: користувач зобов'язаний вручну ввести двозначне число з екрана комп'ютера у додаток на телефоні.
* **Контекстні дані:** Сповіщення у додаток додатково транслюють геолокацію входу та назву програми, що запитує доступ.

**<span>2. Опишіть формат JSON: де він використовується, які його особливості. Чи застосовується цей формат у Azure?</span>** <br>
**JSON (JavaScript Object Notation)** — це текстовий формат представлення та серіалізації структурованих даних. Він спирається на дві базові структури: колекції пар «ключ: значення» (об'єкти `{}`) та впорядковані масиви значень (`[]`).

**Особливості формату:**
* Легкий синтаксис та зручність для читання людиною;
* Швидкий аналіз (парсинг) у всіх сучасних мовах програмування;
* Гнучка структура без жорсткої схеми даних.

**Застосування формату JSON у хмарі Azure:**
У Microsoft Azure JSON є базовим стандартом:
1. **ARM-шаблони (Azure Resource Manager Templates):** Опис хмарної інфраструктури за методологією Infrastructure as Code (IaC) створюється у вигляді JSON-файлів.
2. **Конфігураційні файли:** Налаштування у сервісах Azure Functions (`host.json`, `local.settings.json`) використовують JSON.
3. **Обмін даними через Azure REST API:** Усі запити й відповіді між клієнтом та Azure Control Plane передаються у JSON.
4. **Вивід Azure CLI:** За замовчуванням усі команди CLI повертають результати у JSON.

--------------------------------------------------------------------------------

**<span>3. Які є види Azure API? Коротко опишіть їх.</span>** <br>
Платформа Microsoft Azure надає кілька категорій програмних інтерфейсів API:
1. **Azure Resource Manager (ARM) REST API (Control Plane APIs):** Інтерфейси для керування ресурсами хмари (створення, налаштування та видалення ВМ, сховищ, мереж).
2. **Data Plane APIs:** Ендпоінти для прямої роботи з даними всередині ресурсів (завантаження об'єктів у Blob Storage, надсилання повідомлень у Queue).
3. **Microsoft Graph API:** Єдиний API для доступу до об'єктів Microsoft Entra ID (користувачі, групи, ліцензії).
4. **Azure Management SDKs:** Нативні бібліотеки для мов C#, Python, Java, Go, які обгортають REST API у зручні об'єктно-орієнтовані методи.
