**2.1. Випишіть основні поняття та терміни (категорії сервісів, назви сервісів), які були розглянуті у першому відео.**
* **Глобальна інфраструктура (Global Infrastructure):**
    * *Regions (Регіони):* географічно відокремлені кластери ЦОД AWS у всьому світі, що забезпечують мінімальну мережеву затримку та локальне збереження даних;
    * *Availability Zones (AZ, Зони доступності):* повністю ізольовані дата-центри з автономним енергопостачанням та охолодженням у межах одного регіону;
    * *Edge Locations (Точки присутності):* граничні сервери мережі доставки контенту (CloudFront CDN) для кешування статичних ресурсів якомога ближче до клієнта.
* **Обчислювальні сервіси (Compute):**
    * *Amazon EC2 (Elastic Compute Cloud):* оренда віртуальних машин різноманітних апаратних конфігурацій (x86, ARM Graviton);
    * *AWS Lambda:* безсерверне виконання фрагментів програмного коду за подійною моделлю (Serverless / FaaS);
    * *AWS Elastic Beanstalk:* платформа для спрощеного оркестрування, деплою та масштабування вебзастосунків без ручного налаштування серверів.
* **Сховища даних (Storage):**
    * *Amazon S3 (Simple Storage Service):* високомасштабоване об'єктне сховище для файлів, резервних копій та статичних вебресурсів;
    * *Amazon EBS (Elastic Block Store):* блокові накопичувачі (віртуальні жорсткі диски SSD/HDD) для віртуальних машин EC2;
    * *Amazon EFS (Elastic File System):* керована мережева файлова система спільного доступу за протоколом POSIX/NFS;
    * *Amazon S3 Glacier:* холодні архівні сховища тривалого зберігання за мінімальною собівартістю.
* **Керовані бази даних (Databases):**
    * *Amazon RDS (Relational Database Service):* хмарний сервіс для автоматизованого адміністрування СУБД (PostgreSQL, MySQL, MariaDB, Oracle);
    * *Amazon Aurora:* оптимізована високопродуктивна реляційна СУБД від AWS із реплікацією даних у кількох зонах доступності;
    * *Amazon DynamoDB:* надшвидка масштабована NoSQL-база даних із збереженням у форматі «ключ-значення» та документів.
* **Мережеві ресурси (Networking):**
    * *Amazon VPC (Virtual Private Cloud):* ізольоване віртуальне приватне хмарне середовище для побудови захищених топологій підмереж;
    * *AWS Route 53:* глобально розподілена відмовостійка служба керування доменними іменами (DNS).
* **Цінова політика та модель витрат (Pricing):**
    * *Pay-as-you-go:* концепція оплати виключно за фактично використані секунди, години чи гігабайти без фіксованої передоплати;
    * *AWS Free Tier:* програма підтримки нових клієнтів (12 місяців безкоштовних лімітів, безстрокові квоти Always Free та тестові періоди Trials).

**2.2. Для чого потрібна MFA, як її налаштувати в AWS. Наведіть різні варіанти, які були розглянуті у другому відео.**
<br> **MFA (Multi-Factor Authentication / Багатофакторна автентифікація)** призначена для суттєвого підвищення безпеки облікового запису (зокрема головного Root-користувача та адміністраторів IAM). При її активації для входу недостатньо лише статичного пароля — система вимагає додатковий динамічний фактор автентифікації, який змінюється в часі (TOTP-код) або підтверджується фізичним апаратним ключем. Це надійно захищає інфраструктуру навіть у випадку компрометації основного пароля сторонніми особами.
<br> **Порядок налаштування в консолі AWS:**
1. Перейти в меню профілю у верхньому або нижньому кутку консолі та обрати розділ **Manage security and sign-in** (або панель Security Credentials в IAM);
2. У вкладці **Multi-factor authentication (MFA)** натиснути **Register device**;
3. Вказати довільне найменування пристрою та обрати метод генерації одноразових кодів;
4. Відсканувати відображений QR-код за допомогою відповідного застосунку та ввести два послідовні коди перевірки для підтвердження синхронізації часу.
<br> **Варіанти налаштування, розглянуті у відео:**
* *Virtual Authenticator App (Мобільні застосунки аутентифікації):* програмні генератори кодів TOTP на смартфоні чи ПК (Google Authenticator, Microsoft Authenticator, Twilio Authy);
* *FIDO Security Key (Фізичні криптографічні ключі):* апаратні пристрої за стандартом FIDO2/WebAuthn (наприклад, YubiKey), що підключаються через USB-порт або бездротовий модуль NFC;
* *Hardware TOTP Token (Фізичні токени-генератори):* автономні апаратні брелоки (наприклад, SafeNet/Gemalto) з власним рідкокристалічним дисплеєм для виведення одноразових 6-значних паролів.

**2.3. Для чого потрібен Amazon Budgets? Які є варіанти налаштувань? (на базі другого відео).**
<br> **Amazon Budgets** — це спеціалізований сервіс моніторингу та фінансового планування, який дозволяє відстежувати витрати та використання хмарних сервісів у режимі реального часу, налаштовуючи автоматичні сповіщення при досягненні заданих фінансових порогів для запобігання неочікуваним списанням.
<br> **Основні варіанти конфігурацій з відео:**
* *Zero Spend Budget (Бюджет нульових витрат):* шаблон для користувачів Free Tier, який генерує сповіщення, якщо витрати перевищують мінімальний поріг у $0.01 (інформує про вихід за межі безкоштовних лімітів);
* *Monthly Cost Budget (Щомісячний грошовий бюджет):* задає чіткий фінансовий ліміт (наприклад, $15/місяць) із можливістю налаштування кількох порогів сповіщення — як за фактичними нарахуваннями (Actual, наприклад при 80% і 100%), так і за прогнозними оцінками системи (Forecasted);
* *Usage Budget (Бюджет використання ресурсів):* відстежує витрату ліміту робочих годин конкретного ресурсу (наприклад, 750 годин інстансу EC2 t2.micro чи обсягу передачі трафіку Data Transfer);
* *Savings Plans / RI Budgets:* контроль ефективності використання зарезервованих серверних потужностей.

**2.4. Яке призначення IAM policy? Як налаштувати дозволи для різних користувачів? (на базі другого відео).**
<br> **IAM Policy** — це формалізований JSON-документ, що описує перелік дозволених чи заборонених операцій над ресурсами хмари. Вона є основним інструментом реалізації принципу найменших привілеїв (Principle of Least Privilege).
<br> **Методика налаштування дозволів:**
Згідно з кращими практиками AWS, політики не призначаються кожному користувачу індивідуально. Замість цього створюються функціональні групи користувачів (IAM User Groups, наприклад `developers`, `devops`, `auditors`), до яких приєднуються необхідні політики доступу. Користувачі додаються до цих груп і автоматично успадковують їхні права, що суттєво спрощує адміністрування та запобігає виникненню надлишкових прав.

--------------------------------------------------------------------------------

**2.5. Які варіанти додавання IAM policy є при створенні нового користувача, опишіть коротко кожен з них (на базі другого відео).**
1. **Add user to group (Включення до групи користувачів):** користувач зараховується до складу певної IAM-групи і автоматично отримує всі повноваження, призначені цій групі (рекомендований галузевий підхід).
2. **Copy permissions (Копіювання дозволів):** система повністю дублює набір прав та прив'язаних політик від уже наявного користувача-зразка.
3. **Attach policies directly (Пряме призначення політик):** адміністратор безпосередньо вибирає та приєднує до профілю конкретні керовані політики (AWS Managed або Customer Managed Policies) без використання груп.

--------------------------------------------------------------------------------

**2.6. Опишіть як можна писати і застосовувати політики для контролю доступу через IAM Policies (на базі третього відео).**
<br> Структура будь-якої IAM-політики складається з масиву `Statement`, де описуються такі обов'язкові параметри:
* *Effect:* вказує результат перевірки — `Allow` (дозволити) або `Deny` (заборонити; явна заборона завжди має пріоритет над будь-яким дозволом);
* *Action:* точний перелік викликів AWS API (наприклад, `"s3:GetObject"`, `"ec2:DescribeInstances"`, `"rds:CreateDBInstance"`);
* *Resource:* однозначний ідентифікатор ресурсу ARN (Amazon Resource Name), над яким дозволяється операція (наприклад, `"arn:aws:s3:::my-app-storage/*"` або `"*"` для всіх сумісних ресурсів);
* *Condition (опціональний блок):* додаткові безпекові фільтри, за яких дія стає чинною (наприклад, запит виключно з корпоративного IP-діапазону, обов'язкова активна сесія MFA або обмеження за часом доби).

--------------------------------------------------------------------------------

**2.7. Опишіть як перемикатися між ролями для безпечного доступу до різних ресурсів за допомогою Switching IAM Roles (на базі третього відео).**
<br> Функція Switching IAM Roles дозволяє авторизованому користувачу тимчасово змінити контекст прав доступу і прийняти цільову роль у поточному або іншому (Cross-Account) акаунті без повторного введення паролів.
<br> **Процес перемикання:**
У правому верхньому кутку AWS Management Console потрібно натиснути на ім'я облікового запису, обрати пункт **Switch Role**, зазначити 12-значний номер цільового акаунта (Account ID), точну назву ролі (Role Name) та вибрати візуальний колір плашки для швидкої ідентифікації сесії в інтерфейсі. Після підтвердження служба безпеки AWS STS генерує тимчасові токени з новими правами.

--------------------------------------------------------------------------------

**2.8. Опишіть як обмежити максимальні дозволи для IAM ролей і користувачів з використанням Permissions Boundary (на базі третього відео).**
<br> **Permissions Boundary (Межі дозволів):** це механізм вищого рівня контролю прав, який використовує окрему політику для встановлення максимального ліміту (стелі) повноважень, які користувач чи роль взагалі здатні отримати. Навіть якщо користувачу додано найвищу політику `AdministratorAccess`, він фактично зможе виконати лише ті дії, які одночасно дозволені і його основною політикою, і політикою Permissions Boundary (зона перетину прав). Це запобігає самовільному розширенню повноважень користувачами.

--------------------------------------------------------------------------------

**2.9. Як відстежувати і аналізувати дії користувачів та сервісів в AWS за допомогою CloudTrail (на базі третього відео)?**
<br> Сервіс **AWS CloudTrail** забезпечує глобальне журналювання та безпековий аудит усіх операцій в інфраструктурі AWS. Він реєструє кожен виклик API, здійснений через графічну вебконсоль, утиліту AWS CLI або програмний SDK.
<br> У підрозділі **Event History** ведеться журнал дій за останні 90 днів. За кожною подією можна перевірити: точний час виклику, хто саме ініціював запит (IAM-користувач чи роль), IP-адресу клієнта, ім'я викликаного API-методу (`RunInstances`, `PutObject`), вхідні параметри та результат операції (успіх або відхилення з помилкою `AccessDenied`).

--------------------------------------------------------------------------------

**2.10. Яке призначення Policy Simulator, для чого його використовують?**
<br> **IAM Policy Simulator** — це графічний діагностичний інструмент AWS для попереднього тестування створених політик безпеки. Він дозволяє адміністраторам перевірити, чи матиме користувач або роль доступ до виконання певних операцій над заданими ресурсами ще до того, як політики будуть застосовані у реальному середовищі, що допомагає оперативно виявляти помилки конфігурації.

**Файл-довідка з базових команд та структури AWS CLI:**
*   *Загальна структура виклику:*
    `aws <сервіс> <підкоманда> [параметри/опції]`
*   *Базові системні та службові команди:*
    *   `aws help` — відкриття головного вбудованого довідника командного рядка AWS CLI;
    *   `aws <service> help` — перегляд інструкції та переліку підкоманд обраної служби (наприклад, `aws s3 help`, `aws ec2 help`);
    *   `aws configure` — ініціалізація та редагування ключів авторизації, регіону та формату виводу;
    *   `aws sts get-caller-identity` — інспектування інформації про поточного автентифікованого суб'єкта (Account ID, User ID, ARN);
    *   `aws s3 ls` — перегляд переліку наявних S3-бакетів;
    *   `aws ec2 describe-instances` — отримання параметрів та статусів віртуальних машин EC2;
    *   `aws iam list-users` — перегляд переліку користувачів в IAM;
    *   `aws budgets describe-budgets --account-id <ID>` — вивід активних бюджетних лімітів акаунта.


##### Контрольні питання

**<span>1. В чому суть TOTP аутентифікації? Наведіть приклади.</span>**
TOTP (Time-based One-Time Password / Тимчасовий одноразовий пароль) — це криптографічний алгоритм (стандарт RFC 6238), що генерує тимчасові динамічні коди (зазвичай 6 цифр з періодом дії 30 секунд). Генерація базується на гешуванні спільного секретного ключа (Shared Secret Key) та поточного квантованого системного часу Unix Timestamp. Оскільки клієнтський генератор і сервер автентифікації синхронізовані в часі, вони одночасно отримують ідентичне значення. Перехоплений одноразовий код стає непридатним через 30 секунд, що унеможливлює його повторне використання в несанкціонованих цілях. Приклади застосування: додатки Google Authenticator, Microsoft Authenticator, 2FAS, Bitwarden та апаратні токени YubiKey.


**<span>2. Опишіть формат JSON: де він використовується, які його особливості. Чи застосовується цей формат у AWS?</span>**
JSON (JavaScript Object Notation) — це стандартизований відкритий текстовий формат представлення структурованих даних, заснований на парах «ключ: значення» (об'єкти `{}`) та впорядкованих послідовностях елементів (масиви `[]`). Основними перевагами JSON є його простота, висока швидкість синтаксичного розбору (парсингу) комп'ютерними мовами та зручність читання людиною. У платформі AWS формат JSON є ключовим базовим стандартом: він використовується для визначення прав доступу (IAM Policies, Service Control Policies, Bucket Policies), у шаблонах Infrastructure as Code (AWS CloudFormation), як основний формат обміну даними через AWS REST API та виводу відповідей утиліти AWS CLI, а також для журналювання безпекових подій у службах CloudTrail та CloudWatch.


**<span>3. Які є види Amazon API? Коротко опишіть їх.</span>**
*   **REST API:** стандартизовані сервіси на базі протоколу HTTP/HTTPS, що використовують методи GET, POST, PUT, DELETE, є стейтлес (без збереження стану) та підтримують детальне налаштування авторизації й кешування через Amazon API Gateway.
*   **HTTP API:** полегшена та швидша версія RESTful API від API Gateway зі зниженою затримкою та меншою вартістю викликів, призначена переважно для інтеграції з безсерверними функціями AWS Lambda або проксування запитів до контейнерних сервісів.
*   **WebSocket API:** двосторонні повнодуплексні вебз'єднання з постійно активним сеансом, що використовуються для сервісів обміну даними у реальному часі (чати, біржові котирування, повідомлення).
*   **AWS Service APIs (Query / Control Plane APIs):** низькорівневі внутрішні системні інтерфейси самої платформи AWS, за допомогою яких утиліти командного рядка (CLI) та бібліотеки SDK керують життєвим циклом інфраструктурних ресурсів.


**<span>4. Як можна встановити AWS CLI під різними операційними системами?</span>**
*   **Microsoft Windows:** завантаження та виконання офіційного пакета MSI-інсталятора або встановлення за допомогою системного менеджера пакунків `winget install Amazon.AWSCLI`.
*   **Apple macOS:** завантаження інсталяційного пакета .pkg із майстром встановлення або через термінальний менеджер пакунків Homebrew командою `brew install awscli`.
*   **Linux:** завантаження офіційного архіву дистрибутива з документації AWS, його розпакування та виконання системного скрипта встановлення `aws/install`.


**<span>5. Розгляньте базові команди AWS CLI. Наведіть приклади.</span>**
*   *Ідентифікація та перевірка прав поточного сеансу:*
    ```bash
    aws sts get-caller-identity
    ```
*   *Створення нового відра (бакету) в об'єктному сховищі S3:*
    ```bash
    aws s3 mb s3://my-cloud-storage-bucket-2026
    ```
*   *Завантаження локального документа до хмарного бакету:*
    ```bash
    aws s3 cp report.txt s3://my-cloud-storage-bucket-2026/
    ```
*   *Перегляд списку зареєстрованих облікових записів користувачів IAM:*
    ```bash
    aws iam list-users
    ```
*   *Отримання переліку запущених віртуальних інстансів EC2:*
    ```bash
    aws ec2 describe-instances --filters "Name=instance-state-name,Values=running"
    ```

##### Висновки
У ході виконання лабораторної роботи №3 було детально опрацьовано практичні та теоретичні аспекти знайомства з хмарною екосистемою Amazon Web Services (AWS):
1. Успішно пройдено повний процес реєстрації акаунту AWS Free Tier та первинного налаштування його безпеки: активовано двофакторну автентифікацію (MFA) для захисту облікового запису Root за допомогою алгоритму TOTP, а також створено бюджет нульових витрат (Zero Spend Budget) у сервісі AWS Budgets для запобігання виходу за межі безкоштовних квот та уникнення фінансових ризиків.
2. Досліджено механізми сервісу IAM (Identity and Access Management) з розмежування прав за принципом найменших привілеїв. В умовах системного обмеження на створення груп (*Account Verification Hold*) успішно реалізовано практичне розмежування повноважень шляхом прямого призначення керованих політик `PowerUserAccess` та `ReadOnlyAccess` трьом користувачам.
3. Встановлено, сконфігуровано та практично протестовано консольну утиліту AWS CLI. На практиці перевірено ієрархію політик хмари (пріоритет глобальних політик SCP організації над локальними правами користувача IAM), підтверджено валідність авторизації через службу AWS STS та розроблено зручну структуровану довідку українською мовою з базових команд управління ресурсами AWS.
