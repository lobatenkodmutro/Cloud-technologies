**2.1. Що таке віртуальна машина та які особливості їх реалізації у Google Compute Engine?** <br>
**Віртуальна машина (Virtual Machine, VM)** є програмною комп'ютерною системою, що функціонує в ізольованому віртуалізованому середовищі на базі фізичних хост-серверів під управлінням гіпервізора. Вона виділяє віртуалізовані обчислювальні ядра (vCPU), оперативну пам'ять (RAM), блокові дискові накопичувачі та мережеві адаптери, реалізуючи модель обслуговування **IaaS (Infrastructure as a Service)** і забезпечуючи адміністратору повну свободу конфігурування гостьової ОС (Linux або Windows) та прикладного програмного стеку.

**Ключові особливості виконання віртуальних машин у сервісі Google Compute Engine (GCE):**
1. **Глобальна високошвидкісна інфраструктура та гіпервізорна платформа:** GCE функціонує на власному програмному гіпервізорі Google (KVM), який працює поверх власної оптоволоконної мережі Google із мінімальною мережевою затримкою між дата-центрами.
2. **Кастомні конфігурації (Custom Machine Types):** На відміну від багатьох інших хмарних провайдерів, GCE дозволяє інженерам довільно комбінувати точну кількість vCPU та обсяг оперативної пам'яті під конкретне навантаження без переплати за стандартні фіксовані сети.
3. **Гнучкі серії екземплярів (Machine Families):**
   * *General-purpose (E2, N2, N2D, C3D):* збалансовані обчислення за вигідною вартістю для веб-серверів, середовищ розробки та баз даних середнього розміру (тип e2-micro підтримує пільговий тариф GCP Free Tier);
   * *Compute-optimized (C2, C2D, C3):* високочастотні процесори для обчислювальних задач, кодування відео та моделювання;
   * *Memory-optimized (M1, M2, M3):* екстремальний обсяг RAM (до кількох терабайт) для обробки баз даних у пам'яті (In-Memory DB, SAP HANA);
   * *Accelerator-optimized (A2, G2):* конфігурації з графічними прискорювачами NVIDIA (A100, H100, L4) для штучного інтелекту, рендерингу та нейромереж.
4. **Технологія беззупинкової міграції (Live Migration):** При проведенні регламентних технічних робіт чи оновленні серверного обладнання Google автоматично переносить працюючу віртуальну машину на інший фізичний хост у фоновому режимі без її вимкнення або перезавантаження.
5. **Дискова підсистема Persistent Disks:** Гнучке підключення мережевих накопичувачів (Standard HDD, Balanced SSD, Extreme SSD) з підтримкою гарячого розширення обсягу та інкрементних Snapshot-знімків.

**2.2. Які можливості надає Google App Engine для розгортання веб-застосунків?** <br>
**Google App Engine (GAE)** являє собою повністю керовану **PaaS-платформу (Platform as a Service)**, орієнтовану на автоматизоване розгортання, виконання та масштабування веб-застосунків і сервісів без потреби в ручному налаштуванні серверів, ОС або мережевого екрана.

**Основні переваги та функціональні можливості Google App Engine:**
* **Автоматичне автомасштабування (Auto-scaling):** Платформа самостійно виділяє обчислювальні ресурси під час пікового напливу відвідувачів та автоматично зменшує їх кількість до нуля (Scale to Zero) у години відсутності трафіку.
* **Два середовища виконання:**
  * *Standard Environment:* швидкодіюче середовище із зумовленими рантаймами (Python, Java, Node.js, Go, PHP, Ruby), що забезпечує миттєвий запуск та мінімальні витрати;
  * *Flexible Environment:* запуск додатків у довільних Docker-контейнерах на базі ВМ Compute Engine із підтримкою кастомних системних бібліотек.
* **Вбудована підтримка версіонування та канареєчного деплою (Traffic Splitting):** Можливість одночасного утримання кількох версій додатку з поступовим перенаправленням відсотка користувацького трафіку на нову версію.
* **Інтегрована інфраструктура:** Автоматичне надання SSL/TLS-сертифікатів, захист від DDoS-атак, вбудоване проксі-кешування та нативна синхронізація зі сховищами Cloud SQL і Firestore.

**2.3. Які основні кроки створення App Engine-додатка через Google Cloud Console?** <br>
Послідовність дій для створення та розгортання додатка в сервісі Google App Engine через графічний веб-інтерфейс Google Cloud Console включає такі етапи:
1. **Вибір або створення проєкту:** У консолі GCP відкрити меню проєктів та створити новий проєкт (або вибрати існуючий).
2. **Ініціалізація App Engine:** У лівому меню обрати вкладку **App Engine** та натиснути **Create Application**.
3. **Вибір регіону розгортання:** Вказати географічний дата-центр (наприклад, `europe-west1`), в якому функціонуватиме додаток та його база даних (регіон обирається один раз для всього проєкту).
4. **Вибір мовного середовища та типу сервісу:** Обрати мову програмування (Python, Node.js тощо) та тип середовища (*Standard* або *Flexible*).
5. **Завантаження коду та файлу конфігурації `app.yaml`:** За допомогою терміналу Google Cloud SDK або Cloud Shell виконати команду `gcloud app deploy`, яка зчитує конфігураційний файл `app.yaml`, пакує вихідний код і завантажує його на платформу.
6. **Тестування та перевірка:** Натиснути кнопку **Browse** або перейти за адресою `https://<project-id>.<region_id>.r.appspot.com` для перевірки роботи розгорнутого сайту у браузері.

**2.4. Які особливості реалізації Identity and Access Management (IAM) у GCP?** <br>
Система **Cloud IAM (Identity and Access Management)** у Google Cloud Platform забезпечує централізований та гранульований контроль авторизації за принципом найменших привілеїв («хто», «які дії» і «над якими ресурсами» може виконувати).

**Ключові архітектурні особливості Cloud IAM у GCP:**
1. **Концепція триади авторизації:**
   * *Principal (Суб'єкт):* хто запитує доступ (Google Account, Service Account, Google Group або домен Cloud Identity);
   * *Role (Роль):* впорядкований набір дозвільних операцій (Permissions);
   * *Resource (Ресурс):* об'єкт GCP, до якого надається доступ (проєкт, бакет Cloud Storage, ВМ Compute Engine).
2. **Типологія ролей у GCP:**
   * *Basic / Primitive Roles (Базові):* застарілі глобальні рівні `Owner` (повні права + IAM), `Editor` (зміна ресурсів) та `Viewer` (тільки читання);
   * *Predefined Roles (Передвизначені):* вузькоспеціалізовані ролі Google для конкретних сервісів (наприклад, `Compute Instance Admin`, `Storage Object Viewer`);
   * *Custom Roles (Користувацькі):* сформовані адміністратором унікальні набори конкретних `permissions` під завдання компанії.
3. **Ієрархія успадкування прав (Resource Hierarchy):** Права доступу каскадно успадковуються зверху вниз за схемою: `Organization -> Folder -> Project -> Resource`.
4. **Сервісні акаунти (Service Accounts):** Спеціальні системні облікові записи для безпечної взаємодії програмних додатків чи ВМ між собою без використання особистих паролів розробників.

**2.5. Розкрийте використання версій (Versions) у App Engine для управління оновленнями додатків.** <br>
Механізм **версіонування (Versions)** у Google App Engine виступає основним інструментом безпечного управління релізами та безперервної доставки (CI/CD). При кожному виклику команди деплою платформа створює новий автономний екземпляр (версію) коду, не видаляючи попередній.

**Переваги та сценарії використання версій:**
* **Миттєве відкочування (Instant Rollback):** У разі виявлення критичної помилки у новому релізі адміністратор може в один клік переключити 100% трафіку назад на стабільну попередню версію без повторної збірки коду.
* **Розподіл трафіку (Traffic Splitting / A/B Testing):** Можливість плавно пропорційно розподіляти вхідний трафік між кількома версіями (наприклад, 90% на `v1` і 10% на `v2`) за IP-адресою, Cookie чи рандомно для тестування оновлень під реальним навантаженням.
* **Паралельне проведення тестів:** Незалежний запуск нової версії на окремому URL для внутрішнього QA-тестування до її публічного виходу.

**2.6. Здійсніть огляд Cloud Storage та його ключових функцій.** <br>
**Google Cloud Storage (GCS)** є високомасштабованим об'єктним сховищем (Object Storage), розробленим для довготривалого та безпечного зберігання будь-яких неструктурованих даних (медіафайлів, баз даних, документів, резервних копій) у вигляді об'єктів у спеціальних контейнерах — бакетах (Buckets).

**Ключові функції та можливості Cloud Storage:**
* **Безлімітна ємність та надійність:** Автоматичне масштабування обсягу зберігання з гарантією надійності зберігання даних 99.999999999% (11 semiresilient nines).
* **Глобальний доступ через REST API:** Швидкий доступ до об'єктів за унікальним URL або через бібліотеки SDK/gcloud CLI.
* **Керування життєвим циклом (Object Lifecycle Management):** Налаштування автоматичних правил для автоматичного переведення застарілих файлів у дешеві класи сховища або їх остаточного видалення через заданий час.
* **Безпека та версіонування (Object Versioning):** Захист від випадкового перезапису чи видалення файлів шляхом збереження попередніх ревізій об'єктів, а також автоматичне шифрування даних на стороні сервера (SSE) ключами Google або AES-256.

**2.7. Охарактеризуйте різні класи сховищ у GCP: Standard, Nearline, Coldline, Archive.** <br>
Сервіс Google Cloud Storage надає уніфікований доступ до 4 класів зберігання об'єктів, що розрізняються за частотою зчитування, мінімальним терміном зберігання та тарифікацією:

| Клас сховища GCP | Призначення та частота доступу | Мін. термін зберігання | Тарифікація (зберігання / зчитування) |
| :--- | :--- | :--- | :--- |
| **Standard Storage** | Активні «гарячі» дані з частим зчитуванням (веб-сайти, медіастримінг, бази даних). | Відсутній (0 діб) | Найвища вартість зберігання Гб, але безкоштовне або найдешевше зчитування. |
| **Nearline Storage** | Дані з рідким доступом (зчитування не частіше 1 разу на місяць: місячна звітність, бекапи). | 30 діб | Помірна ціна зберігання, невелика плата за зчитування даних. |
| **Coldline Storage** | Дані з дуже рідким доступом (зчитування не частіше 1 разу на квартал: квартальні архіви, логи). | 90 діб | Низька вартість зберігання, підвищена тарифна ставка за зчитування. |
| **Archive Storage** | Довготривалий «холодний» архів (зчитування рідше 1 разу на рік: аудиторські дані, регуляторний архів). | 365 діб | Мінімальна ціна зберігання Гб, але найвища плата за зчитування об'єктів. |

**2.8. Опишіть, як працювати з Cloud Storage на прикладі використання мови Python або C#.** <br>
Програмне управління бакетами та завантаження файлів у Google Cloud Storage мовою Python реалізується за допомогою офіційного пакета `google-cloud-storage`.

**Послідовність виконання у коді Python:**
```python
import os
from google.cloud import storage

def upload_file_to_gcs():
    # Налаштування шляху до файлу авторизаційних ключів сервісного акаунту
    os.environ["GOOGLE_APPLICATION_CREDENTIALS"] = "/path/to/service_account_key.json"
    
    bucket_name = "my-rpz34-cloud-bucket-2026"
    source_file_path = "C:/data/report.pdf"
    destination_blob_name = "reports/2026_report.pdf"

    # Ініціалізація клієнта та завантаження об'єкта
    storage_client = storage.Client()
    bucket = storage_client.bucket(bucket_name)
    blob = bucket.blob(destination_blob_name)
    
    blob.upload_from_filename(source_file_path)
    print(f"Файл успішно завантажено в сховище GCS: {blob.public_url}")
```

**2.9. Що таке Serverless та особливості його реалізації у Cloud Functions і Cloud Run?** <br>
**Serverless (Безсерверні обчислення)** — це сучасна концепція розробки програмного забезпечення, за якої хмарний провайдер повністю бере на себе виділення, обслуговування, масштабування та вивільнення серверної інфраструктури, а користувач сплачує виключно за фактичний час виконання коду.

**Особливості реалізації в безсерверних сервісах GCP:**
1. **Google Cloud Functions (FaaS):** Призначені для виконання невеликих фрагментів коду (функцій), які автоматично викликаються у відповідь на події (HTTP-запити, завантаження файлу в Cloud Storage, повідомлення у Pub/Sub).
2. **Google Cloud Run (CaaS):** Керована платформа для запуску будь-яких stateless Docker-контейнерів за лічені мілісекунди з підтримкою будь-яких мов та бінарних залежностей, яка автоматично масштабується від 0 до тисяч контейнерів залежно від вхідного трафіку.

**2.10. Поясніть різницю між автентифікацією та авторизацією. Як поняття IAM Roles і Service Accounts у GCP пов’язані з цими процесами?** <br>
* **Автентифікація (Authentication - AuthN):** Процес **перевірки автентичності особи чи системи** (підтвердження відповіді на питання «Хто ви такий?» за допомогою логіна/пароля, 2FA або ключів).
* **Авторизація (Authorization - AuthZ):** Процес **перевірки та надання конкретних прав доступу** (відповідь на питання «Що вам дозволено робити в системі?»).

**Взаємозв'язок із концепціями GCP:**
* **Service Accounts (Сервісні акаунти):** Слугують інструментом **автентифікації** для робочих навантажень (додатків, ВМ, контейнерів), надаючи їм унікальну системну ідентичність.
* **IAM Roles (Ролі IAM):** Забезпечують механізм **авторизації**, зв'язуючи автентифікований користувацький або сервісний акаунт із чітким набором дозволених дій над ресурсами GCP.

#### Файл-довідка з базових команд та синтаксису Google Cloud SDK (gcloud CLI)

* **Загальна структура команди:**
  `gcloud <компонент/сервіс> <група-ресурсів> <дія/команда> [прапорці та аргументи]`
* **Глобальні параметри виводу результатів:**
  * `--format=table` — вивід даних у вигляді компактної таблиці (за замовчуванням);
  * `--format=json` — повний вивід у структурованому форматі JSON;
  * `--format=yaml` — вивід у форматі YAML;
  * `--filter="<умова>"` — фільтрація об'єктів за параметрами (наприклад, `--filter="status=RUNNING"`).
* **Базові команди управління акаунтом та конфігурацією:**
  * `gcloud auth login` — інтерактивна авторизація у браузері;
  * `gcloud auth list` — список авторизованих облікових записів;
  * `gcloud config list` — перегляд поточних налаштувань активної конфігурації;
  * `gcloud config set project <PROJECT_ID>` — вибір робочого проєкту GCP;
  * `gcloud projects list` — перегляд усіх доступних проєктів користувача.
* **Керування віртуальними машинами (Compute Engine):**
  * `gcloud compute instances list` — перегляд списку віртуальних машин;
  * `gcloud compute instances create <VM_NAME> --zone=<ZONE> --machine-type=<TYPE>` — створення нової віртуальної машини;
  * `gcloud compute instances start <VM_NAME> --zone=<ZONE>` — запуск зупиненої ВМ;
  * `gcloud compute instances stop <VM_NAME> --zone=<ZONE>` — зупинка віртуальної машини;
  * `gcloud compute instances delete <VM_NAME> --zone=<ZONE>` — остаточне видалення ВМ;
  * `gcloud compute ssh <VM_NAME> --zone=<ZONE>` — безпечне підключення по SSH за допомогою метаданих GCP.
* **Керування об'єктним сховищем (Cloud Storage):**
  * `gcloud storage buckets list` — список доступних бакетів;
  * `gcloud storage buckets create gs://<BUCKET_NAME> --location=<LOCATION>` — створення нового бакета;
  * `gcloud storage cp <LOCAL_FILE> gs://<BUCKET_NAME>/` — завантаження файлу в бакет.

##### Відповіді на контрольні питання

**1. В чому суть TOTP аутентифікації? Наведіть приклади в контексті Google Authenticator та GCP (Google Cloud Platform).** <br>
**TOTP (Time-based One-Time Password / Тимчасовий одноразовий пароль)** — це стандартизований криптографічний алгоритм генерації одноразових динамічних паролів (специфікація RFC 6238), заснований на обчисленні хеш-функції HMAC від комбінації таємного ключ-секрета (Shared Secret) та поточного виміряного системного часу (Unix Timestamp). Кожен код виводиться у вигляді 6 цифр і залишається дійсним протягом вузького часового вікна (зазвичай 30 секунд), після чого автоматично анулюється.

**Контекст Google Authenticator та GCP:**
* **Нативна підтримка OATH TOTP:** Додаток Google Authenticator функціонує як автономний генератор одноразових кодів, який не потребує підключення смартфона до мережі Інтернет у момент авторизації.
* **Захист входу в Google Cloud Console:** Активація 2-Step Verification для облікового запису Google вимагає введення TOTP-коду після стандартного пароля, що унеможливлює несанкціонований доступ з боку зловмисників навіть при компрометації первинного пароля.
* **Безпека сервісних облікових записів та ключів:** У GCP двофакторна автентифікація захищає доступ до панелі IAM & Admin, упереджуючи компрометацію прав адміністратора хмарної інфраструктури.

**2. Опишіть формат JSON: де він використовується, які його особливості. Чи застосовується цей формат у GCP?** <br>
**JSON (JavaScript Object Notation)** являє собою легковагий текстовий формат серіалізації та структурування даних, побудований на синтаксисі об'єктів JavaScript, але незалежний від конкретних мов програмування. Він оперує двома ключовими структурами: наборами пар «ключ: значення» (об'єкти у фігурних дужках `{}`) та впорядкованими масивами значений (у квадратних дужках `[]`).

**Основні переваги та особливості формату:**
* Висока читабельність людиною та простота форматування;
* Легкість синтаксичного аналізу (парсингу) у всіх мовах програмування;
* Відсутність надлишкових тегів порівняно з XML, що зменшує обсяг мережевого трафіку.

**Використання формату JSON у Google Cloud Platform:**
У сервісах GCP формат JSON виступає ключовим системним стандартом:
1. **Основний формат обміну в GCP REST API:** Усі запити та відповіді між клієнтами та GCP Control Plane передаються у форматі JSON.
2. **Формат відповідей CLI-утиліти gcloud:** При використанні прапорця `--format=json` команда повертає дані у вигляді розширених JSON-масивів.
3. **Файли ключів сервісних акаунтів (Service Account Keys):** Приватні ключі для авторизації програм у GCP експортуються у вигляді зашифрованих `.json` файлів.
4. **Конфігурація та логування:** Сервіс Cloud Logging формалізує системні події у вигляді JSON-структур (LogEntry JSON).

**3. Які основні API надає Google Cloud Platform? Коротко охарактеризуйте їх призначення.** <br>
Платформа Google Cloud надає розгалужену систему програмних інтерфейсів API, розгрупованих за основними технологічними напрямами:
1. **Compute & Management APIs (Управління обчисленнями):**
   * *Compute Engine API:* створення та адміністрування віртуальних машин і дисків;
   * *App Engine Admin API:* управління веб-додатками, версіями та розподілом трафіку;
   * *Kubernetes Engine (GKE) API:* автоматизація оркестрації контейнерів.
2. **Storage & Database APIs (Зберігання та бази даних):**
   * *Cloud Storage API:* програмний доступ до об'єктного сховища GCS;
   * *BigQuery API:* виконання аналітичних SQL-запитів над надвеликими масивами Big Data;
   * *Cloud SQL Admin API / Firestore API:* управління реляційними та NoSQL базами даних.
3. **AI & Machine Learning APIs (Штучний інтелект):**
   * *Vertex AI API, Cloud Vision API, Cloud Translation API:* інтеграція моделей ML, розпізнавання образів та перекладу текстів у додатки.
4. **Identity & Security APIs (Безпека та ідентифікація):**
   * *Cloud IAM API:* управління ролями, правами доступу та сервісними акаунтами.
